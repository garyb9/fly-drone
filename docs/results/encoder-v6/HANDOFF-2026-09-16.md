# Handoff — independent re-evaluation of the v6 retinotopic encoder (2026-09-16)

**Audience:** the agent (or human) taking over v6 after a handoff.
**Purpose:** an independent read of the v6 evidence, so the next pass re-checks the load-bearing
claims instead of continuing on momentum. This is not a rewrite of
[`docs/superpowers/plans/2026-09-16-fly-drone-06-retinotopic-encoder.md`](../../superpowers/plans/2026-09-16-fly-drone-06-retinotopic-encoder.md);
it is the "what would falsify this" list.
**State at handoff:** working tree clean, HEAD `db674fe`. The run has produced a clone but **no v6
decoder yet**.

---

## 1. Verdict in one paragraph

v6 is a real, correctly-motivated widening of the sensory interface (8 global scalars → 816
retinotopic currents), and it is the direction the goal wants. But **nothing in the current
artifacts shows that the connectome's own loom/escape circuit is what drives behaviour**: E1 has
not been measured on v6, the run crashed before producing a decoder, and the clone warm start
leaves the *primary* motion channel (Tm4/T2) at neutral by design. The user's observation that
looming/escape groups "look unactivated" in Signals & Controls is a **viewer telemetry gap**, not
evidence of connectome bypass — but it also is not evidence *for* organic use. Treat v6 as
"promising and unproven", not "working".

---

## 2. Facts: what v6 injects and what the decoder reads

| Thing | Value | Source |
| --- | --- | --- |
| Injected (encoder output) | `mi1, tm3, tm4, t2` at `12×8`; `lc4, lplc2` at `4×3`; per side | `retinotopy.py:27-32` |
| Injected volume | 816 currents over ~479 patch roles | `spatial_encoder.flat_dim()`, `retinotopy.define_roles` |
| **Not** injected | `looming`/`escape`/`wing` groups; no motor or descending cell is ever injected | `brain.py:196` (`input_ids` = CHANNEL_ORDER only) |
| Decoder input | 2,022 traces = 1,314 `descending_neuron` + 708 `vnc_motor` | `brain.py:163-167`; counts verified from `cells.json` |
| Escape cells in that input | `DNp01` = cell indices 0,1, group `descending_neuron` | `groups.json` readout role `escape`; `cells.json[0:2]` |
| Wing motor cells in that input | `MNwm*` in `vnc_motor`; `wing_l/r` = 30/30 | `groups.json`, `cells.json[319,321]` |

So "the escape group" and "the wing group" are **already inside the decoder's observation**. What
does not exist is a *labelled output* for them, and the viewer does not display them (finding F1).

The fly-playground groups (`looming`, `escape`, `wing_l/r`, `thrust`, plus `walk/feed/groom/...`
from `build_body_mappings.py`) belong to a **compact 1,585-cell circuit** with engineered body
readouts; the same cells sit first in this repo's full graph (`manifest.json core_count=1585`) but
free-roam maps to 4 body commands by design (`docs/free-roam.md` §2). Not injecting walk/feed/groom
is correct.

## 3. Findings, ranked by how much they should change the next step

### F1 — The viewer cannot show v6 sensory groups or the escape/wing readouts (high)

- `web/src/main.ts:561-565` labels the sensory panel with a hardcoded
  `["light L","light R","loom L","loom R"]` and maps over `f.cues`. Under v6 `f.cues` is 816 long,
  so the first four bars are **mislabeled** and the other 812 render as `undefined`.
- `web/src/main.ts:566-573` shows only `power_l/power_r/steer_l/steer_r`. `brain.read()` also
  returns `escape`, `wing_l`, `wing_r`, `thrust` (`brain.py:130`), but they are dropped.
- The server already sends the full vectors (`server.py:392-393`). The loss is entirely in the
  front end.
- **Fix direction:** have the server emit a version-agnostic sensory summary and let the UI render
  it. `BrainRuntime` knows the layout, so add e.g. `sensory_groups()` returning group means:
  v6 → `light/motion/loom` × `L/R` (mean over each group's maps from `current_maps`); v5 → same
  groups from the 8 channels; v4 → `light L/R, loom L/R`. Add `sensory?: Record<string, number>`
  to the frame, render it with the existing `meters()` (max 2), and extend the readout list to
  include `escape`, `wing_l`, `wing_r`. Fall back to the old `f.cues` path if `sensory` is absent,
  so an older server still works.

### F2 — The clone leaves the primary motion channel unseeded (high)

`spatial_clone.py:26` (`UNSEEDED`) fixes `tm4_l/r`, `t2_l/r` at `neutral=1.0`; the clone only fits
`mi1/tm3` (light) and `lc4/lplc2` (direct loom) to v4's cues. Consequence, measured:

| Artifact | light | motion (Tm4/T2) | loom (LC4/LPLC2) |
| --- | --- | --- | --- |
| `runs/v6/clone/clone.json` | r 0.412 | MSE 5.1e-10, **r null** | r 0.390 |
| `runs/v6/clone-test/clone.json` | r 0.408 | MSE 3.3e-05, **r null** | **r 0.161** |

The M1b gate made Tm4 the **primary** retinotopic channel (Tm4 → LC4 0.292, escape 0.535) and T2 the
strongest driver; both start at a constant 1.0, so at round 0 the loom signal reaches the graph only
through the direct LC4/LPLC2 route — i.e. approximately the v4 scalar, spatialised. **Do not expect
E1 to move at round 0.** Options to settle in the next pass:
1. Seed `tm4/t2` from the v4 loom cue (broadcast, as `lc4/lplc2` already are). Cheap, but
   reproduces the global scalar at init; SAC must still learn the spatial part.
2. Build a per-patch temporal-difference target from the stored v5 clone stacks. Stronger, but the
   patch↔visual-field correspondence is unverified (`specs/...-v6-design.md` §7), so this risks
   supervising the encoder against a coordinate system that means nothing.
3. Leave neutral and justify it explicitly as "SAC must discover Tm4/T2" — acceptable only if a
   later round demonstrably moves E1/E2 relative to F2's neutral baseline.

### F3 — Task 10 did not complete; the run stopped after the clone (high, procedural)

`runs/v6/stage-round0.log:76-89` shows `roam-collect` failing with
`KeyError: 'extractor'` — `distill.collect` called `LearnedEncoder.load` on a v6 file. That is
fixed in `87d9ce6` (`distill.py:88-98` now dispatches on `_is_spatial`). The clones themselves are
valid (`runs/v6/clone/encoder.pt`, `runs/v6/clone-test/encoder.pt`). The re-evaluation should re-run
Task 10 (teacher collection under the clone → round-0 decoder → 30-seed gate) **before** any E1/E2
claim.

### F4 — E1 has never been measured on v6 (high, decisive)

The v6 rationale is E1 ≥ 0.8. Baselines: v4 policy-flown **0.687**, v4 fixed probe **0.732**
(`runs/v5/e1-v4-baseline.json`, `runs/v5/e1-v4-fixed.json`, both `passed: false`). No v6 E1 report
exists. Command once a v6 decoder/encoder exists:

```bash
env -u PYTHONPATH .venv/bin/fly-drone encoder-checks \
  --policy <v6-decoder.json> --encoder <v6-encoder.pt> \
  --output runs/v6/e1e2-fixed.json --episodes 50 --seconds 120 --workers 6 --controller teacher
```

Run the `teacher` (fixed-probe) variant for the encoder comparison; the `policy` variant mixes in
behaviour (`roam_eval.py:453-497`). A miss is a **reported fail**, never a threshold move.

### F5 — The probe assay is all zeros, and should be explained or ignored (medium)

`runs/probe/spatial_assay.json` reports `0.0` for every uniform/dark-/bright-loom condition and only
`v4_loom_escape = 0.1535`. If that is the intended fixed-probe baseline, say so; if it is a broken
probe, it is currently the only "assayed" v6 artifact and will mislead.

### F6 — Clone held-out fits are weak across the board (medium)

Even the seeded channels clone at r ≈ 0.25–0.41 (per-channel table in `runs/v6/clone/clone.json`).
This is not fatal (v5's clone lessons allowed a weak fit plus balanced sampling), but it means the
warm start gives SAC little more than a rough initialisation, and the `motion r: null` rows must not
be read as "trained".

   `arena.LEVELS`).

## 5. Guardrails (do not violate while re-evaluating)

- Connectome frozen: no wiring/weight/sign/parameter/tonic-bias change.
- Do **not** inject into `looming`/`escape`/`wing`/descending/motor cells. Injection is sensory-only;
  injecting behaviour is scripting and breaks the goal contract (`docs/overview/README.md` §1).
- The decoder's only input stays the 2,022 DN + VNC traces; no pose/target/pixels.
- `roam_eval.ACCEPTANCE` and E1/E2 bars are never relaxed. A miss is reported.
- Ask the user before long runs (clone, every SAC round, DAgger, evaluation). ≤ 6 workers.
- Never edit `python/fly_drone/*.py` while a `sac-round`/`roam-*` subprocess is live.
- Commit and push after each task; no agent trailer.
