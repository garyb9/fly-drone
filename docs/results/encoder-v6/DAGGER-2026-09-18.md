## Why: the threat drive is ~1% of the data

Adding level 3 did not give the threat drive enough frames, because the level mix dilutes it:

| set | samples | threat frames | threat share |
| --- | ---: | ---: | ---: |
| d2 (24 L3 flights) | 72,000 | 703 | **1.0%** |
| d3 (24 L3 flights) | 72,000 | 758 | **1.1%** |

Class-balanced fitting up-weights those frames, but there are too few: `it2` threat held-out R²
**−1.10** (32 held-out frames), `it3` **−1.13** (133), with train R² 0.18–0.38. So the threat head
is neither well-represented nor measurably realisable from these data.

This matches the v6 spec §5, which already called for a **threat curriculum** ("threats-without-
pillars training level") and dense threat shaping precisely because threats are 3–7/episode and
lateral/vertical get no gradient otherwise. Plan 08 Task 3 said "include recovery-focused threat
frames" but left the level mix at the default, which did not do that.

## Recommendation

Before any decoder SAC (Task 4), run a **threat-focused DAgger iteration** initialised from `it2`
(or `it1`): collect at **level 3 only** (e.g. 96–128 flights) so the threat drive is tens of
percent of the data, refit, and screen. If dodge then rises with a positive causal gap, proceed to
SAC; if it does not, the frozen encoder's DN representation likely cannot carry the threat cue
(E1 loom 0.720), which is the Option-2 trigger (decoupled critic), not a teacher/data problem.

  −1.10 → −0.55.
- **Cost: foraging.** Beacons fell 1.60 → 0.80 (below the round gate ½·round0 = 1.0), and the

  threat. This is a trade-off, not a regression of the pipeline.

So the curriculum hypothesis holds (more threat frames → causal dodge), but `it3t` is not a
shippable student. Next: decoder SAC from `it3t` with the behaviour-cloning anchor (plan 08
Phase 4), to keep the dodge while the reward recovers foraging.
