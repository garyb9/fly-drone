# P2 connectome-constrained dynamics — prior gate (negative)

**Status:** recorded 2026-09-19. P2 infrastructure is landed (per-neuron dynamics, additive
alternate bundle) but the only declared prior available — Shiu-2024 uniform LIF — **does not
beat the canonical uniform LIF** on the causal gates. Per the spec's P2 falsifier
(§6: "If fitted dynamics do not beat uniform LIF on the causal gates, do not adopt"),
the canonical bundle is kept and no fit is run. There are no recorded activity data in-repo,
so a recording-fitted array remains the open P2 step.

- Bundle: `data/malecns-dynamics` (`dynamics = shiu-2024-lif-v1`), generated by
  `scripts/make_dynamics_bundle.py`; `bundle_hash = c1a1387d96ab…`
- Adapter: `docs/results/adapter/adapter-dynamics.json` (`declared-v1:d860482b7e3dab18`)
- Gate report: `docs/results/dynamics/adapter-check-smoke-15seeds.json`
- Command: `fly-drone adapter-check --episodes 15 --seconds 120 --level 3 --workers 6 \
  --seed-base 1000 --no-probes --bundle data/malecns-dynamics \
  --adapter docs/results/adapter/adapter-dynamics.json`
- Runtime: 2 773 s. **Non-pre-registered** (15 seeds, not the 50-seed protocol); the full gate was
  skipped because the effect is null-to-negative and this is a declared prior, not a fit.

## What the prior actually changes

The Shiu-2024 mapping (`python/fly_drone/dynamics.py`) normalises threshold above rest to the
canonical unit and reuses the canonical time constants, so its per-neuron arrays are numerically
identical to the canonical bundle. The only effective difference is the scalar `noise_sigma`
(0.02 → 0.0):

| Parameter           | Canonical | Shiu prior |
| ------------------- | --------: | ---------: |
| `leak`              |    0.7788 |     0.7788 |
| `v_threshold`       |       1.0 |        1.0 |
| `refrac` (ticks)    |         0 |          0 |
| `v_reset`           |       0.0 |        0.0 |
| **`noise_sigma`**   | **0.02**  |  **0.00**  |

So this gate tests **removing intrinsic membrane noise**, not per-neuron leak/threshold dynamics.
That is stated plainly here; it is not evidence about the per-neuron infrastructure's value.

## Result (seeds 1000–1014, intact adapter condition)

Compared against the canonical `adapter-check.json` restricted to the same seeds with the same
aggregation (`distill.summarise`):

| Metric               | Canonical 15 | Shiu prior 15 |    Δ |
| -------------------- | -----------: | ------------: | ---: |
| `beacons_per_min`    |        0.033 |         0.000 | −0.033 |
| `collisions_per_min` |        1.200 |         0.967 | −0.233 |
| `near_dodge_rate`    |        0.670 |         0.707 | +0.037 |
| `balanced_dodge_rate`|        0.600 |         0.681 | +0.081 |
| `mean_visited_cells` |         8.27 |          6.93 | −1.33 |
| `slow_fraction`      |        0.627 |         0.673 | +0.046 |
| `mean_abs_yaw_bias`  |       0.0113 |        0.0152 | +0.004 |

`acceptance.passed = false` (A1 foraging 0.00 beacons/min; A6 coverage 2.7%, slow 67.3%). The
`zero`/`shuffle` ablations are byte-identical between the two bundles, and the teacher / cue-script
/ random baselines match exactly — the runs are deterministic given a bundle, so the deltas on the
intact condition are the prior's effect. That effect is at or below the noise floor and in the
wrong direction for foraging and coverage.

## Interpretation

A declared Shiu-2024 prior that maps onto the canonical constants cannot demonstrate P2. Replacing
it with a recording-fitted per-neuron array is the only way to test the infrastructure, and that
requires activity recordings that are not in this repository. No fit will be run against invented
targets. The canonical bundle stays the identity; `data/malecns-dynamics` stays as an additive,
git-ignored alternate for future fitting.
